AgendadorCron únicoDe 5 em 5 minutos
  • Sem framework MVC: cada ecrã é um script PHP servido por um router central (router.php), com reescrita de URL pelo Apache (.htaccess).
  • Layout comum (cabeçalho, menu, rodapé) com o tema Gentelella; cada ecrã carrega apenas as bibliotecas de que precisa.
  • Multi-tenant: o NIF de login escolhe a base de dados e a pasta de ficheiros do tenant; cada pedido corre no contexto desse tenant.
  • Área do cliente servida no mesmo código, em rotas t/{tenant}/cliente/....

Instalação

composer install                  # dependencias PHP
mysql -u root -p < schema.sql     # esquema inicial
php scripts/migrate.php           # aplicar migracoes
# configurar data/db.php (ligacao) e data/companies.php (tenants por NIF)
php -S localhost:8001 router.php  # servidor de desenvolvimento
  1. Aponte o vhost para a pasta da aplicação e confirme a reescrita para router.php.
  2. Registe cada tenant (NIF → base de dados, credenciais, identificador curto) no ficheiro de empresas.
  3. Aplique as migrações a cada base (pela linha de comandos ou, como superadmin, pelo aviso de migrações pendentes na aplicação).
  4. Entre como administrador e siga a ordem de configuração recomendada.
  5. Configure o cron único (ver abaixo).

Base de dados e migrações

  • Todas as alterações de esquema são migrações SQL versionadas por data (pasta migrations/), aplicadas por scripts/migrate.php e registadas na tabela migrations.
  • Os campos do ERP (prefixos str*, int*, flt*) não existem na base local: são lidos em tempo real pelo ERP-SINC.

Tarefas agendadas

Há um único cron no servidor, de 5 em 5 minutos, que executa as tarefas devidas registadas na aplicação (scripts/cron-jobs.php). Cada tarefa declara o âmbito (por empresa ou global), a periodicidade e a função a correr; o estado e um bloqueio evitam execuções sobrepostas.

*/5 * * * * php /caminho/app/scripts/calendar-push.php --url=https://app.exemplo.pt/
30 3 * * *  /bin/bash /caminho/app/scripts/cleanup-caches.sh
  • php scripts/cron-run.php --list mostra as tarefas e a última execução; --job=nome corre uma já.
  • A limpeza diária apaga caches regeneráveis (imagens de leitura de QR, pré-visualizações, logs de E-fatura, temporários), sem tocar nos PDF/XML. Sem ela, as caches crescem sem limite.

Segurança

  • Autenticação: palavras-passe com hash forte (bcrypt/argon via password_hash), política mínima de complexidade, recuperação por ligação temporária.
  • Sessões: cookies HttpOnly e SameSite; proteção CSRF em todos os formulários e pedidos AJAX.
  • Isolamento: base de dados e ficheiros por tenant; permissões por perfil, departamento e empresa cliente.
  • Segredos: senhas do E-fatura e campos de palavra-passe cifrados; chaves de serviços só visíveis a administradores.
  • Pasta de dados bloqueada ao acesso web, exceto os pontos de entrada necessários.
  • Auditoria: alterações relevantes, impersonações e instruções IA ficam em audit_logs.
  • IA: modo seguro por utilizador; nenhuma escrita sem permissão e confirmação.

Cópias de segurança

  • Diárias: todas as bases de tenant (dump MySQL) e as pastas uploads/ e attachments/.
  • Ficheiros de configuração (data/db.php, lista de tenants, chaves VAPID das notificações). Não regenerar as chaves VAPID: as subscrições push existentes deixam de funcionar.
  • As caches de leitura não precisam de backup.
